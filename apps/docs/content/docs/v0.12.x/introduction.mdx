# Better Auth for Payload CMS

You are one plugin away from revolutionizing your Payload CMS authentication system. This plugin seamlessly integrates [Better Auth](https://www.better-auth.com) with [Payload CMS v3](https://payloadcms.com), providing enhanced authentication capabilities.

## Why this plugin?

While Payload CMS comes with a solid and extensible authentication system out of the box, it primarily focuses on basic email/password authentication and API keys. Modern applications often require more sophisticated authentication methods and features.

This plugin bridges that gap: Better Auth becomes the authentication engine, Payload stays your database and admin UI, and everything in between - collections, endpoints, admin screens - is generated for you.

## Key features

<Tabs items={['Authentication', 'Admin UI', 'Developer Experience']}>
  <Tab value="authentication">
    <ul>
      <li>Unified Better Auth strategy: email + password, TOTP 2FA, social/OAuth</li>
      <li>Default email verification and password reset flows (overridable)</li>
      <li>Session management handled by Better Auth</li>
      <li>Role-based access control via the Better Auth admin plugin</li>
    </ul>
    <Link href="features/two-factor">Two-factor authentication</Link>
  </Tab>
  <Tab value="admin-ui">
    <ul>
      <li>Auto-injected social login buttons in the Payload admin login screen</li>
      <li>2FA setup prompt before the dashboard, plus setup/verify views</li>
      <li>Account-level controls (TwoFactorAccountButton)</li>
    </ul>
    <Link href="features/social-login">Social login</Link>
  </Tab>
  <Tab value="developer-experience">
    <ul>
      <li>Collections auto-generated from your Better Auth options</li>
      <li>Payload endpoints bridged to Better Auth (`/login`, `/logout`, `/me`, ...)</li>
      <li>Per-collection overrides via `extendsCollections`</li>
      <li>`payload.betterAuth` instance, fully typed with your own plugin options</li>
      <li>Auth layer helpers for Next.js (checkers, guards, server actions)</li>
    </ul>
    <Link href="api/exports">API Reference</Link>
  </Tab>
</Tabs>
